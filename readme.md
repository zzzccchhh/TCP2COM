# ESP-01S / ESP32-C5 / ESP32-S3 网络串口上位机

Python 网络到串口桥接工具，支持 TCP 客户端、TCP 服务端、固定对端 UDP、原生 USB 日志与设备配置。提供 React 桌面工作台、局域网多端页面、Tkinter 界面和命令行入口。

[Gitee 仓库](https://gitee.com/zch_good/esp-tcp2com) · [GitHub 仓库](https://github.com/zzzccchhh/TCP2COM) · [在线工作台](https://zzzccchhh.github.io/TCP2COM/) · [配套 C5 固件](https://gitee.com/zch_good/esp-c5-wifi)

在线工作台运行界面；服务电脑上的 Python 后端负责实际网络、COM 和 USB 操作。手机浏览器控制的也是服务电脑，不直接占用手机串口。

## 当前设备能力

| 项目 | ESP-01S | ESP32-C5 | ESP32-S3 |
|---|---|---|---|
| Wi-Fi | 2.4 GHz | 2.4 GHz / 5 GHz / AUTO | 2.4 GHz |
| 业务接口 | 配套 UART 固件 | UART 原始 0、UART GPIO 流控 3、四线 SPI 写入 4 | UART 原始 0、SPI WBR 1、UART WBR 2 |
| 原生 USB 配置/诊断 | 不提供 | 支持 | 支持 |
| 配网按键 | 按配套固件说明 | GPIO24，长按至少 3 秒 | GPIO4，长按至少 3 秒 |
| 配网热点 | 按配套固件说明 | `ESP32-C5-Setup` | `ESP32-S3-Setup` |
| 网络角色 | 以固件能力为准 | TCP 服务端/客户端、UDP | TCP 服务端/客户端、UDP |

**C5 旧 SPI WBR=1、UART WBR=2 已移除。** C5 SPI=4 仅支持 MCU → C5 → 网络，电脑发向设备的业务数据不会交给 MCU。两种 C5 UART 继续双向透传，S3 原接口保持不变。

## 配置 ESP 与配置电脑是两件事

设备配置决定 ESP 的接口、Wi-Fi、网络角色、端口、缓存和 GPIO 选择，需要读取当前设备后明确保存并重启。电脑桥接配置决定本程序连接哪个 IP、监听哪个端口、使用哪个 COM，点击启动桥接后使用。

| 电脑角色 | ESP 应配置为 | 关键字段 |
|---|---|---|
| TCP 客户端 | TCP 服务端 | 电脑 `host/port` 指向 ESP 业务地址/端口 |
| TCP 服务端 | TCP 客户端 | ESP 目标 IP 为电脑实际网卡地址，目标端口等于电脑监听端口 |
| UDP | 固定对端 UDP | 双方填写实际 IP 和端口，电脑 `peer_port` 对应 ESP 本地端口 |

`0.0.0.0` 用于电脑监听，不能作为 ESP 连接目标。`192.168.137.1` 只是常见电脑热点网卡示例，实际值以服务管理窗口或 `ipconfig` 为准。业务端口通常为 8080；局域网网页服务默认 8765；外部 MCU 复位控制通常为设备 TCP 8081。

## 配置新版 C5

1. 选择 **ESP32-C5**，连接原生 USB COM；退出占用这个 COM 的其他程序。
2. 长按 GPIO24 至少 3 秒进入配网，点击“读取设备配置”。USB 配置不要求电脑连接 C5 Wi-Fi，也不要求业务桥接运行。
3. 或连接 `ESP32-C5-Setup`，通过 `http://192.168.4.1/` 读取 HTTP 配置。
4. 选择接口、频段、网络角色、地址和端口，检查变更摘要，明确保存并重启。
5. 保存后重新进入配网读取核对。结果未知时先读取，不自动重放保存请求。

接口、GPIO 流控和 SPI 参数以 [C5 固件说明](https://gitee.com/zch_good/esp-c5-wifi) 为准：

| 接口 | 编号 | 接入要点 |
|---|---:|---|
| UART 原始透传 | 0 | 原始字节，默认 8N1，无 GPIO 流控 |
| UART GPIO 流控透传 | 3 | 必须选流控线，高暂停/低允许，MCU 输入上拉 |
| 四线 SPI 简易写入 | 4 | SCK/MOSI/MISO/CS，无 READY、复位线，只上行 |

`flow_pin`：1=GPIO23、2=GPIO10、3=GPIO9、4=GPIO5。模式 3 下流控线不能与启用的外部 MCU 复位线共用，MCU 响应和 DMA 尾随需满足固件预算，默认 5 ms 加 4096 字节尾随数据。

SPI 模式使用 C5 GPIO23 SCK、GPIO10 MOSI、GPIO9 MISO、GPIO5 CS，另需供电和共地。GPIO11/12 不作握手/复位，UART/UHCI 不初始化。UART 波特率、流控线、外部复位选择在 SPI 模式下不启用。

### MCU SPI 库与数据方向

C5 MCU 使用固件仓库 `mcu_library/` 中的 `wifi_spi.c/.h`，本地可导出到 `D:\ESP\spi库`。S3 继续使用其独立三文件库，不混用。

MCU 实现五个板级端口，业务只调用 `wifi_spi_init()` 和 `wifi_spi_write(data,length,&written)`。Mode 3、MSB first，默认起测频率 5 MHz。

- TCP 基本块 512 字节，每批最多 8 块/4096 字节，长调用自动分批，尾部保留真实长度。
- UDP 一次调用对应一包，最大 512 字节，超长拒绝。
- 忙闲和接收结果为短字节；成功只表示 C5 缓存接收，不能证明电脑已收到。
- 初始化使用专用完成标记和一致的身份/模式快照，网络变化不能冒充初始化成功。
- 未确认写入返回不确定状态，应用先处理数据范围，不跨会话盲目重发。
- 电脑网络端接收纯业务载荷，不解析内部 SPI 包头，也不需要向 MCU 回传应答。

上位机仍支持通用双向 COM 桥接；使用 C5 SPI 时只有网络 → 电脑业务 COM 的方向能到达业务接收端，电脑 COM 发出的反向业务数据会被 C5 丢弃。需要指令下发时选择双向 UART 接口。

### 配置迁移与旧备份

新版 C5 API 为 `c5-config-2`。保存使用当前修订号、HTTP 会话或 USB boot/session，不能根据旧读取结果保存到另一台设备。旧 API 不允许接收新接口编号 4。

旧接口 1/2 的备份和草稿保留网络参数，接口标记为“未选择”，需要重新选择有效接口。旧 SPI 备份中未生效的复位/流控选择以及 8081 端口允许导入；选择 UART 后重新校验端口和 GPIO 冲突。

C5 固件自身迁移旧 SPI NVS 时清除未生效的复位选择、保留有效网络参数并进入恢复。恢复期间不驱动业务引脚，必须明确选择接口、保存重启，不能通过按键绕过。

## 常用连接示例

### C5 主动连接电脑

在设备配置选择接口 4、TCP 客户端，目标 IP 为电脑实际网卡地址，目标端口为 8080，明确保存重启。电脑运行：

```powershell
py -3 -B tcp2com.py --device c5 --mode tcp-server --listen 0.0.0.0 --port 8080 --com COM5 --baud 1152000
```

可用 `--host C5实际IP` 限制来源。电脑服务端只接一个业务连接，断开后继续监听；ESP 重连由设备自己的参数决定。

### 电脑连接 C5 或 S3

设备设为 TCP 服务端，电脑填写设备实际地址：

```powershell
py -3 -B tcp2com.py --device c5 --mode tcp-client --host 192.168.4.1 --port 8080 --com COM5
py -3 -B tcp2com.py --device s3 --mode tcp-client --host 192.168.4.1 --port 8080 --com COM5 --usb-port COM8 --usb-log s3-usb.log
```

USB 日志 COM 和业务 COM 必须不同。S3 使用 2.4 GHz，按 GPIO4 进入配网；其原始 UART 和 WBR 接口行为以配套 S3 固件为准。

### C5 单向 SPI UDP

设备选择接口 4、UDP，远端为电脑实际 IP:8080，本地端口例如 6060。电脑运行：

```powershell
py -3 -B tcp2com.py --device c5 --mode udp --listen 0.0.0.0 --port 8080 --host 192.168.137.200 --peer-port 6060 --com COM5 --udp-payload 512
```

`host` 替换为 C5 实际 IP。`--udp-payload` 控制电脑本地 → 网络的分包，不会改变 MCU 库的 512 字节报文上限；该模式的反向数据不会送到 MCU。

### JSON profiles

```powershell
py -3 -B tcp2com.py --config tcp2com_config.json --profile c5-spi-tcp --com COM5
py -3 -B tcp2com.py --config tcp2com_config.json --profile s3-client --com COM5
py -3 -B tcp2com.py --list-coms
```

JSON 仅在显式指定时读取，命令行覆盖 profile。profiles 配置电脑连接，不会自动修改 ESP 的 `link_mode`、网络角色或 NVS。使用前检查 IP、COM、端口，不把默认示例当作已接好的设备。

## 本机桌面与局域网多端

本机工作台支持网络/USB 状态、流量监测、日志过滤、配置编辑、备份导入、草稿恢复及外部主控复位。最小化继续工作，关闭窗口释放连接。流量曲线以实际运行状态采样，单独连接 USB 不生成业务流量；UDP“已绑定”不等于对端在线。

需要手机或其他电脑控制时，启动 `启动_局域网服务.vbs`，使用管理窗口生成的完整链接或二维码：

- 持有效连接链接的浏览器自动连接，无需额外批准；这些客户端可以操作服务电脑的 COM、USB 和设备设置。
- 二维码和本地工作台进入局域网页面，构建后不依赖外网；在线工作台也可连接同一个服务。
- 多网卡时选择浏览器可访问的电脑地址，`127.0.0.1` 仅供服务电脑自身使用。
- 多端同步运行状态与当前配置；有冲突时重新读取并保留草稿，不覆盖其他终端的新版本。
- 管理窗口可刷新链接、撤销客户端。浏览器关闭不会停止后端正在运行的桥接。
- 关闭管理窗口停止服务并释放设备；重新启动后使用新的有效连接链接。

服务端记住网卡、监听地址/端口和来源设置，同网卡换 IP 后更新地址与二维码，每 5 秒检查，也可手动刷新。固定在线网址可以恢复浏览器上次的有效后端；首次访问没有记录时，先使用完整链接或电脑局域网地址。

无管理窗口运行：

```powershell
py -3 -B -X utf8 lan_service.py --headless --listen 0.0.0.0 --port 8765
```

开发预览在 `frontend` 执行 `npm run dev`。未接入后端时显示预览，不提供真实设备操作。连接本地 Vite 页面需在服务参数明确允许实际来源，例如 `--origin http://127.0.0.1:5173`。

## 配置、草稿和密码

设备读取后才能保存。切换型号、地址、配置连接方式或 USB COM 会使旧读取依据失效；切回原选项也要重新读取。

设备备份使用 `wifi-bridge-user-config-v1`，兼容旧 `c5-user-config-v1`；导入只改编辑区。备份、恢复草稿及自动保存不包含密码、读取会话或清空密码意图。密码空白表示保留，清空 STA 密码需要明确选择，AP 密码不能清空。

`tcp2com_last_state.json` 保存电脑设置和无密码草稿，`lan_service_state.json` 保存服务参数，两者均为本地文件。启动不自动连接、不向 ESP 写入。JSON profiles、未保存草稿和设备已保存 NVS 是不同层次，保存设备以弹窗确认后的结果为准。

## 外部主控复位

三个设备使用各自的独立 TCP 控制协议，不能混用。打开复位窗口本身不发请求，从首次点击起 3 秒内点击 5 次才发送一次，结果未知不自动重试。

- C5：配置中启用所选复位线后，仅 UART 模式生效，默认关闭；SPI=4 不提供外部 MCU 复位输出。
- S3：按配套固件的复位线和接口规则设置。
- ESP-01S：原命令行入口可按 R 或点击底部入口打开窗口，`--no-reset-ui` 可禁用；GPIO0 接外部 MCU 低有效复位脚，外部上拉 3.3 V。

这些控制服务用于可信网络，不等同硬件急停。关闭正在复位的面板不会撤销已发送请求，应查看设备状态和最终结果。

## 业务 COM、性能和诊断

连接真实业务串口，或把数据送入虚拟 COM 对的一端，让已有业务上位机打开另一端。同一个 COM 不能被两个程序同时占用。USB 日志/配置使用独立原生 USB COM。

本地 `--baud` 只设置电脑业务 COM，不改变 ESP UART 波特率或 MCU SPI 时钟。真实串口 1,152,000 baud、8N1 的理论载荷约 115.2 kB/s，可能成为 SPI/Wi-Fi 链路瓶颈；虚拟 COM 是否受波特率限制取决于驱动。

TCP 接收队列满时使用背压；串口短写保留后缀重试。状态分别统计网络接收、本地写入、本地到网络、积压和丢弃，不把网络入队等同于本地完整写入。日志最多缓存 3000 行，可过滤、搜索、暂停和导出。

| 现象 | 检查方向 |
|---|---|
| 配置读取返回 403/静默 | 是否已进入正确型号的配网状态 |
| 读取依据失效或保存结果未知 | 重新进入配网读取，不直接重放保存 |
| 设备连不上电脑监听端 | 电脑实际网卡 IP、防火墙、网络角色、端口、ESP 重连设置 |
| UDP 已绑定但没有数据 | 对端 IP/端口、MCU 是否持续发送，UDP 本身不证明在线 |
| C5 SPI 收不到下发指令 | SPI=4 仅上行，需要双向业务时选择 UART |
| 网络快而 COM 慢、队列上涨 | 业务 COM 波特率、虚拟串口驱动、接收程序和消费速度 |
| 新页面仍显示旧接口 | 更新 Python 后端及本地前端，重启旧服务，刷新网页并重新读取设备 |
| 最小化后无数据或持续掉线 | 查看实际运行状态、USB stats、网络错误和串口写入耗时 |

吞吐测试应使用足够长的数据量和内容校验，分开观察 MCU → C5 入队与电脑实际接收。C5 固件提供单向 `tools/spi_receive.py`，不要求 MCU 回传业务数据；CRC、DMA、电气和持续无线速度仍需板端验证。
