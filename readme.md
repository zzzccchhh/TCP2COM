# TCP ↔ COM 桥接上位机

将 TCP 服务端与本地串口双向连接，支持二进制透传、自动重连和实时速率显示。配合 ESP-01S 新版固件，可从命令行点击入口打开独立急停窗口，远程复位外部单片机。

```text
电脑本地串口 ↔ tcp2com.py ↔ TCP 8080 ↔ ESP-01S ↔ 外部单片机 UART
命令行入口 → 急停窗口 → TCP 8081 → ESP GPIO0 → 外部单片机复位脚
```

## 安装与快速启动

安装 Python 3；使用复位弹窗时，Windows Python 安装需包含 Tcl/Tk。唯一第三方运行依赖为 `pyserial`。以下命令均在**本上位机仓库根目录**执行：

```powershell
py -3 -m pip install -r requirements-tcp2com.txt
py -3 tcp2com.py --list-coms
py -3 tcp2com.py --host 192.168.137.200 --port 8080 --control-port 8081 --com COM5 --baud 1152000
```

将目标地址和 `COM5` 替换为实际配置。该程序是 **TCP 客户端**，需要 ESP 或其他目标先提供 TCP 服务；本地串口必须存在且未被其他程序占用。

也可编辑 [启动_tcp2com.bat](启动_tcp2com.bat)，再双击启动：

| BAT 配置 | 当前值 | 含义 |
| --- | --- | --- |
| `T2C_HOST` | `192.168.137.200` | ESP 地址 |
| `T2C_PORT` | `8080` | 数据透传端口 |
| `T2C_CONTROL_PORT` | `8081` | 独立复位端口 |
| `T2C_COM` | `COM1` | 本地串口，需修改 |
| `T2C_BAUD` | `1152000` | 本地串口波特率 |
| `T2C_FLOW` | `none` | 默认无硬件流控 |

BAT 保持 ASCII 编码并切换代码页到 UTF-8，中文提示由 Python 输出。ESP UART、外部主控及本地串口各端点应采用匹配的波特率和数据格式，默认 8N1。

## 命令行入口与急停窗口

1. 启动后只显示原命令行，不额外显示图形主窗口，也不自动弹出急停窗口。
2. 命令行底部状态区显示 `[ 打开急停 / 复位窗口 ]`。左键点击入口或按 `R`，打开独立急停窗口；打开动作本身不发送复位命令。
3. 在急停窗口中，从首次点击起 **3 秒内点击 5 次**才发送一次请求。超时清零，等待执行结果期间禁用按钮。
4. 关闭急停窗口只隐藏它，透传与重连继续运行。未触发时清零未完成的点击；已触发时继续等待结果，重新打开保留忙碌状态和结果，不重复发送。
5. 在命令行按 `Ctrl+C` 退出桥接；关闭命令行窗口也会终止程序。

Windows 鼠标入口使用原生控制台事件，运行期间关闭快速编辑以接收点击，正常退出时恢复原输入模式。入口位置随日志、缩放和滚屏更新；窗口很窄时缩写为 `[复位]` 或 `[R]`。

非 Windows 环境、输出重定向或原生控制台不可用时，不提供该入口，并提示后继续桥接；不同终端宿主的鼠标兼容性需实际确认。Tk 不可用时回退为控制台桥接。明确不需要复位功能时增加 `--no-reset-ui`，完全跳过窗口初始化。

## 复位接线与结果含义

- ESP GPIO0 接外部单片机的低有效复位脚，两端共地；复位线需外部上拉到 **3.3V**，不能直接接上拉到 5V 的线路。
- GPIO0 使用开漏输出，平时释放；复位时拉低约 1000 ms，期间 GPIO2 每 50 ms 翻转一次，结束后恢复正常灯态。
- GPIO0 也是 ESP 启动配置脚，需确认上电时外部电路不将其拉低；不要接回 ESP 自身的 RST。
- 只在收到匹配编号的 `DONE` 后显示完成，表示 ESP 已释放复位输出，不表示外部主控完成启动。
- 发送后断网或超时会显示“结果未知”，不会自动重发。已开始的复位由 ESP 自行计时释放；检查设备状态后再决定是否重新操作。

“急停”实际是主控复位，不能替代硬件急停。控制通道没有身份认证，只用于可信局域网，不应开放到公网。控制端口必须与透传端口不同，并与固件配置一致；旧固件不支持时会提示失败，不向透传端口发送复位命令。

## 常用参数

运行 `py -3 tcp2com.py --help` 查看全部参数。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--host`、`--com` | 必填 | TCP 目标及本地串口 |
| `--port`、`--control-port` | `8080`、`8081` | 透传与控制端口 |
| `--baud` | `1152000` | 串口波特率 |
| `--flow` | `none` | 可选 `none`、`rtscts`、`dsrdtr`，须有硬件支持 |
| `--reconnect` | `2` 秒 | 断线重连间隔，`0` 表示不重连 |
| `--keepalive-idle` | `3` 秒 | Keepalive 空闲时间，`0` 表示关闭 |
| `--connect-timeout` | `4` 秒 | TCP 建连超时 |
| `--stats-interval` | `0.25` 秒 | 速率刷新周期，约 1 秒滚动平均 |
| `--no-reset-ui` | 关闭 | 指定后禁用急停入口和弹窗 |
| `-v` | 关闭 | 输出调试日志 |

## 速率与故障排查

- 状态区显示 TCP 收、串口写、TCP→串口队列块数、串口→TCP 速率和双向累计丢弃量。队列最多 128 块，每块 16 KiB，满时暂停 TCP 接收形成背压。
- **队列统计只对应 TCP→串口方向**；队列和丢弃量为 0，不能证明串口→TCP 方向没有阻塞。
- 速率按完成的收发字节计数，批量写入和阻塞发送可能形成短时跳变；排查时结合连接日志及持续吞吐观察。
- TCP/UART 均为字节流，应用层需自行处理图像帧同步、长度和校验；程序不会保留读取块边界。
- 持续输入超过消费能力仍可能造成 UART 溢出；Keepalive 也不能即时发现所有断线，Windows 探测次数可能由系统控制。
- 若电脑上游 5 GHz、热点 2.4 GHz 时抖动，可与上游和热点均为 2.4 GHz 的情况对照，结合无线驱动及热点状态排查，不能仅凭速率跳变判定固件故障。

## 目录与测试

| 路径 | 用途 |
| --- | --- |
| `tcp2com.py` | 串口/TCP 桥接、状态显示、参数入口 |
| `console_control.py` | Windows 控制台鼠标事件、绘制及输入模式恢复 |
| `reset_control.py` | 复位协议、五次点击门限及弹窗生命周期 |
| `tests/` | 协议、点击规则、窗口、控制台和桥接回环测试 |
| `requirements-tcp2com.txt` | Python 运行依赖 |
| `README_tcp2com.txt` | 详细的原有说明及控制协议示例 |

在本仓库根目录执行：

```powershell
py -3 -B -X utf8 -m unittest discover -s tests -v
```

测试使用本地模拟 ESP 服务和 `loop://` 串口回环；Windows 原生控制台测试在独立隐藏进程中验证鼠标、中文布局、缩放、滚屏、Ctrl+C 和模式恢复。缺少 Tk 显示环境时相关测试会跳过。自动化测试不替代实际终端宿主、真实串口、高速 Wi-Fi 链路和 GPIO 波形验证。
