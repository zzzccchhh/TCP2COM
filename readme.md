# ESP-01S / ESP32-C5 / ESP32-S3 网络与串口桥接上位机

## 局域网多端工作台

在线界面：https://zzzccchhh.github.io/TCP2COM/ 。GitHub Actions 在 `main` 更新时构建并发布前端；在线页面沿用新版桌面工作台样式，并支持手机单栏布局。网页操作的 COM、文件和网络均属于运行服务的电脑。

1. 在连接设备的电脑上运行 `py -3 -m pip install -r requirements-lan.txt`；本地网页入口需在 `frontend` 运行 `npm ci`、`npm run build`。二维码使用 qrcode/Pillow 生成，不访问第三方二维码服务。
2. 日常双击 `启动_局域网服务.vbs`，显示服务管理窗口、不弹命令行；`启动_局域网服务.bat` 保留诊断输出。默认监听局域网 TCP 8765，窗口显示在线工作台网址、局域网地址，以及「复制网址」「复制地址」「打开网页」「本地工作台」按钮。按 Windows 提示允许专用网络访问；不要做公网端口映射。
3. 选择手机可访问的网卡地址，复制配对链接或展示二维码。手机、电脑打开后自动填入地址并展开配对面板，也可在网页手动输入 `192.168.1.100:8765`（自动补全 HTTP 协议）。分享链接使用 URL fragment 携带地址，不携带控制凭证、不自动发送配对请求。
4. 网页输入终端名称、点击「请求配对」。服务管理窗口显示请求编号、终端名称、来源 IP 和时间，在本机选择申请并点「允许配对」后网页自动连接；支持拒绝、网页取消及两分钟超时。无需配对码，审批仅限本机管理窗口，远程 HTTP 无审批入口。
5. 若在线页面被浏览器阻止连接，允许该站点的本地网络访问；也可直接打开窗口中的 `http://电脑IP:8765/`，使用本地提供的相同页面。Safari、iOS 及不同版本浏览器对在线 HTTPS 页面访问本地 HTTP 服务的限制不同，请优先使用本地入口。在线页面需要外网，本地入口构建后无需外网；127.0.0.1 仅供服务电脑使用。

已配对终端可以控制桥接、USB、设备配置和复位，并每 250 毫秒同步状态、日志及流量。服务串行执行操作；配置保存要求本终端先读取设备，继续使用固件当前修订号与会话，结果不明时重新读取，不自动重放命令。设置变化通过服务同步，冲突请求会拒绝并提示重试；设备草稿保留在各页面内存中，刷新后需重新编辑。复位点击计数不会在不同终端间累加。

服务管理窗口和网页配对面板均可查看和撤销终端。配对凭证仅保存在当前标签页会话中；服务重启后所有凭证失效，需重新申请。每个来源每分钟最多申请五次，待处理/保留申请最多 64 条，已配对最多 32 个。未允许的申请无法操作设备，审批结果凭申请专属随机凭证查询；取消已批准但尚未完成的申请会撤销对应凭证。所有已配对终端均拥有控制和撤销权限，请仅允许可信终端。本地 HTTP 通信未加密，适用于可信局域网。关闭网页不停止服务；关闭服务管理窗口停止服务并释放设备。不要同时运行桌面版和局域网服务争用同一 COM 口。

自定义启动参数示例：`py -3 -B -X utf8 lan_manager.py --port 8765 --origin https://你的网页域名`。`lan_service.py --headless` 仅用于服务诊断，无审批入口、不能完成新配对。默认仅允许 GitHub 页面来源 `https://zzzccchhh.github.io` 及本地同源网页访问；不开放任意来源，不提供任意 Python 方法调用，也不提供运行文件下载接口。旧配对码接口已移除，更新在线前端时也需要更新并重启本地服务。

自动验证包含隔离的 Python 服务测试，以及两个独立浏览器会话（电脑 / 手机尺寸）的真实 HTTP 配对、设置同步、刷新恢复和撤销测试。测试不打开真实设备；真实手机、HTTPS 在线页到局域网连接、ESP、USB 和高波特率性能仍需实测。

## 新版桌面工作台

新增 QDrive 风格的本地网页界面：暖灰背景、三栏卡片布局、运行日志与流量监测切换、USB 独立连接和设备配置侧栏。新版使用 React / TypeScript / Vite 与 pywebview，数据转发继续使用原 Python 引擎。旧版 `启动_图形界面.bat` 和 CLI 保留。

首次安装需要 Python 3、Node.js（建议 22.12 或更新版本）及 Windows Microsoft Edge WebView2 Runtime：

```powershell
py -3 -m pip install -r requirements-web.txt
cd frontend
npm ci
npm run build
cd ..
py -3 -B tcp2com_web.py
```

日常双击 **`启动_新版界面.vbs`**，通过 `pyw -3` 启动，只显示工作台，不弹出命令行窗口。VBS 与 Python 入口保持在同一个程序目录，路径含空格或中文也可启动；已有构建产物时启动不需要 Node.js。首次缺少 Python 依赖或前端构建时会弹窗提示准备步骤；启动异常会提示错误日志位置，默认位于 `%LOCALAPPDATA%\WiFiBridge\logs\startup.log`，单份最多 512 KiB，保留两份轮转备份，目录不可写时尝试系统临时目录。

`启动_新版界面.bat` 保留为首次构建及命令行诊断入口。构建产物不存在时，它会用 `npm ci` 和 `npm run build` 自动构建，再启动工作台；此入口会显示命令行窗口。修改前端源码后需要重新构建。网页资源打包在本地，不使用在线字体、CDN 或云端服务。

- 左侧设置电脑网络角色、地址与业务 COM；高级串口、超时和重连参数可展开。编辑不会替换正在运行的连接，明确点击“应用并重启”才生效。
- 进入工作台默认显示流量监测，按现有字节计数显示最近约 30 秒的网络接收、COM 写入、网络发送速率。工作区顶部用带底色的状态标识显示 TCP 连接状态：已连接为绿色，等待连接或重连为黄色，未启动为红色。TCP 曲线仅在业务桥接运行且连接建立时采样，未连接、断开或停止时保留当前曲线；重新连接后继续更新。UDP 仍在桥接运行时更新，显示“已绑定”不代表设备在线。单独连接 USB 不会更新流量曲线。状态和采样以实际运行的网络角色为准，尚未应用的编辑不影响判断。切换到运行日志后可查看上位机日志及 ESP（USB）日志；USB 读取的设备输出统一归入 ESP 日志，包含未标注级别的普通文本。支持搜索、按来源筛选、暂停滚动、清空和导出全部缓存日志，最多保留 3000 行。
- 右侧可单独连接或断开 USB。设备配置支持 USB / HTTP 读取、编辑、恢复草稿、撤销、备份与导入；保存前弹窗展示修改摘要，密码内容不显示。旧固件未提供的配置字段保持禁用。
- 底部显示速率、待写队列和累计丢弃；链路诊断包含串口写耗时、短写、超时、UDP 统计、USB stats 更新时间和固件原始字段。
- ESP-01S、C5 与新版 S3 固件支持 3 秒内点击 5 次的外部主控复位操作。
- 自动恢复与旧 GUI 共用 `tcp2com_last_state.json` 格式，启动不自动连接。设备草稿与备份不保存密码或读取会话；设备保存使用当前修订号和会话，保存结果不明时必须重新读取。避免同时运行两个 GUI 编辑同一个状态文件。
- 停止按钮同时关闭业务桥接和 USB；关闭主窗口释放连接并等待配置请求结束，最小化继续转发。

纯浏览器预览仅用于检查界面，页面会明确显示“浏览器界面预览”；连接操作需要从桌面版启动：

```powershell
cd frontend
npm run dev
```

前端检查：`cd frontend` 后运行 `npm run build`、`npm test`。Windows 交互测试使用已安装的 Microsoft Edge；其他平台需安装 Playwright Chromium。桌面集成检查：在仓库根目录运行 `py -3 -B tools/test-webview.py`，默认使用隐藏 WebView2 窗口、临时设置和本地 TCP / `loop://` 串口，不打开真实设备；添加 `--visible` 可检查主窗口实际可见性，`--result-file 路径` 可在 pythonw 下输出验证结果。启动回归包含真实 VBS 调用后的可见窗口检查；VBS 必须正常显示窗口，`pyw` 本身负责避免控制台，不能再用隐藏窗口样式启动。

2026-10-31 验证：202 项 Python 回归全部通过，无跳过；14 项浏览器测试通过，覆盖宽窄窗口、150% DPI、日志积压、配置确认、设备切换及 TCP 断连暂停曲线；TypeScript 检查、生产构建通过。真实 VBS→pythonw 在中文和带空格的目录下启动通过；生产入口的集成验证确认一个实际可见的 WebView 主窗口、零控制台，JS/Python 调用、TCP/串口回环及关闭清理通过。VBS 已改用正常显示窗口的启动样式，修复原先连主界面一起隐藏的问题。以上均为主机验证，尚未进行真实 ESP / USB / 无线吞吐联调。

支持 TCP 客户端、TCP 服务端和 UDP，将网络原始字节与本地 COM 双向桥接。提供中文图形界面和命令行，显示连接、速率、队列和丢弃统计；C5/S3 支持独立 USB 诊断及用户配置读写。提供按设备类型切换的统一远程复位窗口。

```text
业务上位机 ↔ COM 对的另一端 ↔ 本程序 ↔ Wi-Fi ↔ ESP-01S UART / C5、S3 UART/SPI ↔ 主控
                                                └─ C5/S3 原生 USB：日志及配置
```

当前 C5/S3 的 WBR/1 只用于 MCU↔设备的 UART/SPI 链路；电脑网络端接收业务载荷，不解析 WBR/1 包头。
图像帧、波形、指令的长度与校验仍由业务上位机和主控约定。C5 已删除旧逐飞模式，原 `wifi_spi_*` 无法直接连接新 SPI 固件。

## 当前 C5 固件适配

在网络页选择 **ESP32-C5**，打开“ESP32-C5 用户配置”。支持当前固件全部 USB/HTTP 可写用户参数：

| 分类 | 可修改项目 |
| --- | --- |
| MCU 接口 | 0=UART 原始透传、1=SPI WBR/1、2=UART WBR/1，UART 波特率 |
| Wi-Fi | AP／电脑热点／共享 Wi-Fi，2.4 GHz／5 GHz／自动，两组 STA 和 AP 的 SSID、密码及 IP 配置 |
| 网络角色 | TCP 服务端／TCP 客户端／固定对端 UDP，服务端口、目标 IP/端口、本地端口（0 自动分配） |
| 恢复与内存 | 自动重连，重连间隔和连接超时 100～60000 ms；上行 64～6144 KiB、下行 64～2048 KiB，总和最多 6144 KiB |

读取识别 `config_api="c5-wbr-1"`，保留 `revision/saved_revision/unsaved/migration_requires_setup`。
USB 和 HTTP 保存均自动附带**当前读取**的编辑修订号；草稿和备份不会恢复修订号或配网会话。
界面显示临时运行值未保存及旧 SPI 恢复状态；这些状态即使没有字段差异，也允许明确保存并重启。
旧 v3 SPI 迁移时固件暂停业务 UART/SPI，先选择新接口再保存重启。旧固件缺少的网络字段保持禁用；更新后重新读取。

单 Type-C 操作：选择 C5 → USB 及原生 USB COM → 连接／应用 USB → 长按 GPIO24 至少 3 秒后松开 → 读取 → 编辑 → 保存并重启。
不需要启动业务桥接或创建虚拟 COM。普通模式 USB 只输出日志；网页和 USB 都只能在配网时修改用户配置。

## 安装与选择模式

安装 Python 3 和依赖。在本目录打开 PowerShell：

```powershell
py -3 -m pip install -r requirements-tcp2com.txt
py -3 -B tcp2com.py --list-coms
py -3 -B tcp2com.py --help
```

第三方依赖只有 `pyserial`。中文图形界面和 ESP-01S 复位弹窗需要 Python 自带的 Tcl/Tk；C5/S3 命令行自动禁用复位弹窗，不依赖 Tk。网络服务端和 UDP 监听需要允许 Windows 防火墙中的 Python 入站连接。

双击 `启动_图形界面.bat`，或运行：

```powershell
py -3 -B tcp2com_gui.py
```

GUI 与原 CLI 共用桥接引擎；`启动_C5.bat`、`启动_S3.bat`、`启动_tcp2com.bat` 启动命令行。GUI 不要求管理员权限，也不自动更改电脑网卡、热点或安装虚拟串口。

| 运行日志 | 区分上位机与 USB / ESP 来源，可按来源和文字筛选；ESP 日志按级别着色，支持暂停自动滚动、清空和导出；最多保留 3000 行，工作线程事件队列最多 2000 条 |

电脑参数在原有页面直接修改，由软件自动保存和恢复，不需要手动加载配置文件。设置不包含设备 Wi-Fi 密码，也不会写入设备。

编辑参数时现有连接继续运行，底部显示实际使用的设备、网络角色、COM 参数、绑定/对端地址和统计。底部内容会随窗口宽度换行；空间不足时可使用右侧滚动条或将鼠标移至状态区滚动查看。顶部“参数未应用”表示业务参数尚未用于当前连接；点击“应用参数并重启”才释放旧连接并启动新参数。USB 的连接与断开独立于桥接启动和重启；已打开的业务 COM 与 USB COM 必须不同，业务 COM 也不能同时用于 ESP-IDF monitor。配置请求进行时暂停替换连接的操作，关闭主窗口仍可取消等待。

需要使用 ESP-IDF monitor 时，先用顶部总开关关闭 USB，并等待状态显示“已关闭”，然后再打开 monitor；使用上位机 USB 功能前需先退出 monitor。若业务 COM 本身选用了同一物理端口，还需停止桥接或更换业务 COM。命令行显式传入 `--usb-port` 时仍会启动 USB 诊断。

最小化窗口继续透传。关闭主窗口会停止桥接、关闭串口和 USB，并等待正在进行的配置请求返回；关闭复位子窗口仅隐藏它，已发送请求继续等待结果。顶部“远程复位”窗口根据当前设备显示 ESP-01S、C5 或 S3 状态。USB 面板显示已有 `stats` 的原始字段及距更新时间；超过 15 秒标为过期，串口断开显示离线并继续重试，旧数值不能证明设备仍在线。

## 自动记住上次设置

图形上位机在参数变更约 500 ms 后自动记录，正常关闭前再保存一次；记录位于程序目录 `tcp2com_last_state.json`，独立于手动命名的 profiles 文件，并已加入 Git 忽略。程序目录需可写；保存失败会在底部提示，业务转发及关闭流程继续正常运行。

会记住设备和网络角色、目标/监听地址与端口、COM 及串口参数、USB 参数、USB/HTTP 配置方式和配置地址。暂时禁用的输入也保留，例如 TCP 模式下的 UDP 对端端口。未填完的数字和地址作为界面草稿保留，启动前仍按原规则校验。

C5/S3 的设备配置页分别保存非密码草稿，包含三种接口、Wi-Fi 模式、网络角色、目标地址、重连和缓冲参数。恢复时明确显示“尚未读取设备”，不会恢复密码、清空密码意图、设备修订号或已读取的会话身份。保存到 ESP 前必须从当前连接重新读取；新读取会显示设备当前值，旧编辑仍可用“恢复上次草稿”放回编辑区，再按当前读取结果计算修改。此按钮本身不会提交设备配置。

图形界面不再手动管理命名 profiles。已有上次设置优先恢复，旧文件保留；没有状态文件时，仅尝试迁移默认文件的 `c5-spi-tcp`，无法判断先前选中的其他 profile。状态文件损坏或版本不支持时提示并使用内置默认值，启动时不会覆盖损坏文件。命令行和 BAT 仍以显式参数及所选 profile 为准，不读取图形界面设置。

迁移到另一台电脑或目录时，先正常关闭界面，再复制程序目录和 `tcp2com_last_state.json`；状态文件被 Git 忽略，需要单独携带。新电脑的 COM/USB 端口号及日志路径可能不同，请按实际情况调整。恢复界面不会自动连接或写设备；C5/S3 保存设备配置前仍需重新读取当前设备。

## ESP32-S3 N16R8 快速使用

对应当前 `D:/ESP/ESP-S3-WIFI` 固件。S3 使用时在网络页选择 **ESP32-S3** 并设置所需电脑网络角色，修改会自动保存。

| 项目 | 当前 S3 | C5 |
| --- | --- | --- |
| 频段 | 仅 2.4 GHz，`band=0`，信道 1～13 | 保留 2.4/5 GHz/AUTO |
| 配网按键 | GPIO4，长按至少 3 秒后松开 | GPIO24 |
| 原生 USB | GPIO19 D− / GPIO20 D+ | GPIO13 D− / GPIO14 D+ |
| 配网热点 | `ESP32-S3-Setup` | `ESP32-C5-Setup` |
| 出厂 AP 密码 | `change-me-s3` | `change-me-c5` |
| 业务 AP / TCP | `ESP32-S3-Bridge`，`192.168.4.1:8080` | 按 C5 保存配置 |

**USB 单线配置**：选择 ESP32-S3，进入“ESP32-S3 用户配置”，选择 USB 和原生 USB 的 COM，点击“连接 / 应用 USB”。长按 GPIO4 松开进入配网，点击“读取 ESP32-S3”；无需启动业务桥接。编辑后点击“保存并重启 ESP32-S3”并确认。USB 日志与配置只占用一个连接，使用前退出其他占用该 COM 的 monitor 或工具。

**HTTP 配置**：进入配网后，电脑连接 `ESP32-S3-Setup`，使用当前 AP 密码，地址为 `http://192.168.4.1/`。USB/HTTP 都只能在配网模式配置。保存结果不明时先重新进入配网读取核对，不自动重发。

USB 根据 hello 真实型号匹配 C5/S3。新 S3 固件使用 `BRIDGECFG ` v2、`X-Bridge-Session`；电脑端通过只读 HELLO 协商前缀，保存只使用已识别前缀。C5/旧 S3 的 `C5CFG `、`X-C5-Session` 继续兼容。新 S3 的配置修订号用于防止 MCU、网页和电脑相互覆盖旧编辑。

S3 配置页仅显示 2.4 GHz，客户端读取、编辑、导入和保存也校验频段；不把 5 GHz 或 AUTO 静默转换。切换型号、地址、配置连接方式或 USB COM 会清除读取依据及密码编辑；切回原选项也需要重新读取，旧异步结果不会填回当前页面。USB 重连会使旧读取失效。

新备份使用 `wifi-bridge-user-config-v1`，记录设备类型且不含密码和会话；仍可导入旧 `c5-user-config-v1`。跨型号导入按当前选择的能力校验：2.4 GHz 配置可复用，S3 拒绝 5 GHz/AUTO，导入只更新编辑区。

S3 profiles：

| 配置名称 | 电脑角色 | 适用情况 |
| --- | --- | --- |
| `s3-client` | TCP 客户端，连接 `192.168.4.1:8080` | 匹配 S3 出厂 UART 模式及 SPI 默认 TCP 监听 |
| `s3-spi-tcp` | TCP 服务端，监听 `0.0.0.0:8080` | 主控已命令 S3 主动连接电脑 |
| `s3-spi-udp` | UDP，固定对端 `192.168.137.200:6060` | 主控已建立对应 UDP Socket，地址按实际网络修改 |

```powershell
# 编辑 COM1 为自己的业务 COM；也可使用已创建虚拟 COM 对的一端
py -3 -B tcp2com.py --config tcp2com_config.json --profile s3-client --com COM5
# 同时采集原生 USB 日志，USB COM 必须与业务 COM 不同
py -3 -B tcp2com.py --device s3 --host 192.168.4.1 --port 8080 --com COM5 --baud 1152000 --usb-port COM8 --usb-log s3-usb.log
```

电脑连接 S3 热点或配置电脑移动热点时使用 **2.4 GHz**。S3 UART0 是 GPIO11 TX / GPIO12 RX，不是开发板上常见 GPIO43/44。S3/C5 使用各自的 TCP 8081 复位协议。

当前 S3 使用独立 MCU 库 `D:/ESP/库`，支持 UART 原始透传（0）、SPI 协议（1）、UART 协议（2）。SPI/UART 协议提供 MCU 数据收发和配置修改，不使用旧适配文件。先通过 USB/网页选接口；模块网络角色仍需与电脑配套。新配置页可编辑角色、目标 IP/端口、重连和队列参数。车端工程未接入。

兼容保留 `C5Client(url, timeout=4)`、`C5USBClient(monitor, timeout=4)` 和既有导入路径；新调用可传 `device="s3"`。固件仓库原有 S3 命令行配置入口仍可使用，GUI 现在可直接配置 S3。

本轮验证：上位机 Python 测试 205 项通过（1 项跳过），Web 前端 14 项测试通过；S3 固件构建和 USB 配置解析器配对通过。尚未烧录或进行实机复位波形与吞吐验证。

## C5 / S3 外部主控远程复位

新固件的 C5 用户配置提供复位线：关闭、SCK GPIO23、MOSI GPIO10、MISO GPIO9 或 CS GPIO5；选择后保存并重启。仅两种 UART 模式有效，默认关闭，SPI 模式不驱动复位线。S3 对应引脚为 GPIO18/10/9/5；旧固件缺少此字段时界面禁用该项。

统一窗口随主界面设备类型切换：ESP-01S 延续原有桥接要求，C5 和 S3 均可独立填写控制地址。请求进行中切换设备不会改变请求目标，完成前不可再次触发；隐藏窗口后请求继续并保留结果。

选择 C5 或 S3 后点击顶部“远程复位”，输入设备真实 IPv4 地址和控制端口 8081；在 3 秒内点击五次触发。业务桥接无需启动。主控复位线为开漏低有效，约 1 秒后释放；设备数据灯在此期间快速呼吸。控制协议独立于业务连接，无身份认证，限可信网络使用；成功只表示设备已释放输出，无法证明主控完成启动。断线或超时后如果结果未知，先检查主控，不自动重发。接线、电压和上电波形要求见对应固件 README。

## 在 GUI 中读取和修改 C5 配置

推荐 **单 Type-C USB 连接**：

1. 首次通过原生 USB 烧录支持 USB 配置的新 C5 固件；之后用一根支持数据的 Type-C 线连接、供电即可。接口需连到 GPIO13 D−/GPIO14 D+，USB 转 UART0 的 COM 不适用。退出 `idf.py monitor` 或其他占用该 COM 的程序。
2. 打开 GUI，在“网络连接”选择 **ESP32-C5**，到“C5 用户配置”把连接方式设为 **USB**，选择 C5 的 COM，点击“连接 / 应用 USB”。此处与“USB 诊断”的 COM 同步，共用一个串口连接。
3. **长按 GPIO24 按键至少 3 秒后松开**，等待两灯交替闪烁、日志提示 `USB configuration open`。配网初始化成功后点击“读取 C5”。电脑**无需连接 Wi-Fi 或启动业务桥接**；业务 COM、网络端口未配置也可读取。UART/SPI 模式均支持。进入配网会暂停业务透传；普通模式只输出 INFO 及 WARN/ERROR 日志，不响应任何 USB 配置命令。

原 **Wi-Fi HTTP** 方式继续保留：长按 C5 GPIO24 至少 3 秒后松开，电脑连接 `ESP32-C5-Setup`，使用当前 AP 密码（出厂 `change-me-c5`）。连接方式选“Wi-Fi HTTP”，地址默认 `http://192.168.4.1/`，点击“读取 C5”。进入配置热点会中断业务网络；普通业务模式的 HTTP 接口返回 403。

两种方式共用以下编辑及保存流程：

1. 界面显示来源 `defaults`、`nvs` 或旧版迁移来源及读取时间。必须成功读取当前连接后才能保存；切换 USB COM、设备重连、退出再进入配网或改用 HTTP 后需重新读取。
2. 编辑接口与联网、AP、电脑热点 STA、共享 Wi-Fi STA 四个子页。支持三种业务接口、三种联网模式、2.4/5 GHz/AUTO、UART 波特率，以及上述全部网络角色、端口、重连和缓冲参数。AP 支持 SSID/信道/IP/网关/掩码，两组 STA 支持 SSID、DHCP/静态 IP/网关/掩码/DNS。切换模式不会丢弃其他配置。
3. 密码不会从设备返回。**留空保留原密码**，填写才替换；STA 要改为开放网络，勾选“开放网络 / 清空原密码”。AP 密码必须为 8～63 个 UTF-8 字节，不支持清空。SSID 最长 32 字节；中文按 UTF-8 字节计数。保存前校验频段/信道、端口及子网/DHCP 条件。
4. 点击“保存并重启 C5”并确认，仅提交变化的可写字段；成功响应表示已写入 NVS，约 1.5 秒后重启。USB 等待自动重连；USB / HTTP 均需再次长按进入配网后读取核对。业务连接按新地址和端口恢复。修改业务 AP IP 不改变配置热点固定地址 `192.168.4.1`。

“撤销编辑”恢复上次读取内容。“备份”导出当前编辑区，**始终不含密码**；“导入备份”只更新编辑区，不直接写设备。C5 备份格式与电脑 profiles 不同，恢复到另一台设备时需重新填写所需密码。密码仅用于本次请求，不写入本地配置、备份或配置操作日志。

USB 使用协商后的 `C5CFG `（C5/旧 S3）或 `BRIDGECFG `（新 S3）前缀、**版本 2**、唯一请求编号的 UTF-8 JSON 行，先识别设备并读取，再校验并保存。设备启动标识 `boot`、配网会话 `session` 及串口连接代次共同防止提交旧编辑；退出再进入配网也会使旧会话失效。请求行最多 2304 字节、patch 最多 2048 字节。固件和上位机需配套升级，旧版 USB 配置协议不兼容。

普通模式下 `hello/read/validate/save` 全部静默忽略；超时提示会同时提醒进入配网、检查 COM、固件及端口占用，不能仅凭超时判断设备模式。HTTP 使用 `GET/POST /api/config`，不跟随重定向，503 表示配网会话失效或等待重启。两种方式均不自动重发保存：保存后超时、断连或未收到有效确认，显示“结果待确认”，必须重新进入配网并读取，因为 NVS 可能已经写入。业务模式 HTTP 的 403 或 USB 超时不能证明保存失败。旧固件无法识别新 USB 协议时提示超时，不尝试写入。

HTTP 读取还必须返回 `http_session`；保存按固件能力通过 `X-C5-Session` 或 `X-Bridge-Session` 携带该标识。GUI 将地址、启动和配网会话共同绑定到读取结果，拒绝跨配网重入、重启或换设备提交旧编辑。缺少标识的旧固件需同步更新；导入备份不会导入会话。IPv4 各段不允许前导零，例如使用 `192.168.8.200`，不能使用 `192.168.008.200`。

新固件读取当前运行配置，MCU 临时应用后可能与 NVS 保存值不同，界面会显示 `unsaved` 状态。
点击保存才写 NVS；工程中的 `esp32c5_config.h` 仅提供出厂默认值。上下行 PSRAM 队列容量现在可改，保存重启生效；
LED/按键极性、GPIO、MCU 配置开关和 USB SDK 设置仍为编译配置。USB 接口用于可信电脑的本地有线配置。

## 电脑网络角色与 C5/S3 行为对照

| 设备 / 主控行为 | 本程序模式 | 地址及端口含义 |
| --- | --- | --- |
| C5/S3 `net_role=0`：TCP 服务端 | `tcp-client` | `--host` 是设备 IP；`--port` 对应设备 `tcp_port`，默认 8080 |
| C5/S3 `net_role=1`：TCP 客户端 | `tcp-server` | 设备 `remote_ip/remote_port` 指向电脑；`--listen` 是电脑绑定地址，`--port` 是电脑监听端口 |
| C5/S3 `net_role=2`：固定对端 UDP | `udp` | `--port` 对应设备目标端口；`--host` / `--peer-port` 对应设备 IP / 固定本地端口 |

**Wi-Fi 联网方式与 Socket 角色分别配置。** C5/S3 自建 AP、连接电脑热点、共享路由器均可使用；C5 支持双频，当前 S3 仅支持 2.4 GHz。本程序不自动切换电脑热点或网卡。

## C5 示例：SPI WBR/1 + TCP

以下使用 C5 TCP 服务端设置。S3 可在网络页选择 S3 和 TCP 服务端，保持 2.4 GHz。两者 MCU 均使用 `D:/ESP/库` 的三文件库。

1. USB 或网页读取 C5 用户配置，设置业务接口 `1=SPI WBR/1`，联网方式为电脑热点并填写 SSID/密码及频段。
2. 设置设备网络角色 `1=TCP 客户端`，目标 IP 为电脑热点网卡地址，目标端口 `8080`，按需启用自动重连，明确保存重启。
3. 编辑 `tcp2com_config.json` 的 `c5-spi-tcp`，将 `COM1` 改成实际桥接端口；双击 `启动_C5.bat` 开启电脑 TCP 监听。
4. MCU 实现 SPI Mode 3、READY/CS、计时回调，使用 `WB_SPI` 初始化共享库，完成 HELLO 后通过 `wb_write/wb_read` 收发。
   一个请求完成并处理回复后再发下一个，按协商容量及额度分块。接口数值与库 transport 枚举不同，详见 [库说明](../../库/README.md)。

`192.168.137.1` 只是电脑热点网卡 IP 的示例，请用 `ipconfig` 核对。`8080` 是电脑端口，`6060` 是 C5 本地端口。`0.0.0.0` 用于电脑绑定全部 IPv4 网卡，不能填作 CH32 的连接目标。

同样可直接运行：

```powershell
py -3 -B tcp2com.py --device c5 --mode tcp-server --listen 0.0.0.0 --port 8080 --com COM5 --baud 1152000
```

电脑服务端同一时间只接一个连接，立即关闭额外连接。可用 `--host C5实际IP` 筛选来源 IP。
断线后电脑继续监听；设备是否重连由设备的 `auto_reconnect/reconnect_ms` 控制，主动关闭后需明确重新打开。
电脑参数 `--reconnect 0` 只控制电脑 TCP 客户端。MCU HELLO 不修改 Wi-Fi，不隐式切换联网方式或网络角色。

## 电脑主动连接 C5

C5 任一业务接口均可设为 `net_role=0` 提供 TCP 服务端。当前固件头文件默认 UART WBR/1，AP 模板为 `192.168.4.1:8080`，
电脑可在网络页选择 C5 和 TCP 客户端。C5 连接电脑热点或路由器时，使用其实际 IP，可从 USB 日志或终端列表获取。

```powershell
py -3 -B tcp2com.py --device c5 --mode tcp-client --host 192.168.4.1 --port 8080 --com COM5 --baud 1152000
```

SPI WBR/1 和 UART WBR/1 使用同样的独立网络任务；网络角色由保存配置或可信 MCU WBR 命令设置。
现有车端没有在本次修改中接入共享库，使用新协议模式前需由车端维护者完成接入，原始 UART 可继续传输业务字节。

ESP-01S 保持原调用兼容：

```powershell
py -3 -B tcp2com.py --host 192.168.4.1 --port 8080 --com COM5 --baud 1152000
```

不指定 `--device`、`--mode` 时仍默认 `esp01s`、`tcp-client`。原 `启动_tcp2com.bat` 保留当前 `192.168.4.1` 地址以及原有串口、重连和控制端口配置。

## C5 示例：SPI UDP 双向透传

设备配置设为 `link_mode=1`、`net_role=2`，目标 IP 为电脑网卡地址、目标端口 `8080`、固定本地端口 `6060`，保存重启。
电脑可在网络页选择 C5 或 S3 和 UDP，并设置对端地址和端口。主控在协议模式下使用共享库 `wb_datagram`。

电脑对应运行，`192.168.137.200` 必须替换为 C5 当前 IP：

```powershell
py -3 -B tcp2com.py --device c5 --mode udp --listen 0.0.0.0 --port 8080 --host 192.168.137.200 --peer-port 6060 --com COM5 --udp-payload 1200
```

- 只接收指定 C5 IP **和来源端口** 的报文，其他来源计入拒收；地址变化后应重启并更新参数。
- 接收缓冲固定足够容纳 IPv4 最大 UDP 载荷 65,507 字节，不受 `--bufsize` 缩小影响。空报文只统计，不当作断线。
- COM→UDP 按 `--udp-payload` 分包，默认 1200 字节；COM 本身没有报文边界。C5→电脑的大包仍可能发生 IP 分片。
- UDP 不保证送达、去重和顺序，没有 TCP 背压。显示“已绑定”和最近收包时间，不把绑定成功当作设备在线。网络错误时明确报错退出，修复后重新启动。
- WBR/1 UDP 保留报文边界，每帧一个完整报文，最高 4060 字节且受 MCU 协商容量限制；超长报文由固件丢弃并计数。
  原始 UART 模式按有界块发送，不保留串口分块边界。电脑 COM 仍为字节流，需要业务报文边界时应在业务协议中编码。
- 上位机固定过滤设备来源端口，因此双向 UDP 示例要求设备 `local_port=6060`；设备本地端口为 0 时先确认实际端口再配置电脑。

## JSON 配置与启动入口

`tcp2com_config.json` 只保存上位机参数，不存 Wi-Fi 密码，不自动写设备配置。程序仅在显式指定 `--config` 时读取，命令行同名参数优先。

```powershell
py -3 -B tcp2com.py --config tcp2com_config.json --profile c5-spi-tcp --com COM5
```

| Profile | 用途 |
| --- | --- |
| `c5-spi-tcp` | C5 主动连接电脑，电脑监听 TCP 8080 |
| `c5-client` | 电脑连接 C5 默认 TCP 服务端 |
| `c5-spi-udp` | UDP 双向桥接，需修改 C5 实际 IP |
| `s3-client` | 电脑连接 S3 默认 TCP 服务端，`启动_S3.bat` 的默认选择 |
| `s3-spi-tcp` | S3 主动连接电脑，电脑监听 TCP 8080 |
| `s3-spi-udp` | S3 UDP 双向桥接，需修改实际设备 IP |
| `esp01s` | 原 TCP 客户端与独立复位窗口 |

修改 `启动_C5.bat` 或 `启动_S3.bat` 的 `T2C_PROFILE` 即可选择模式，也可从终端传入额外参数。两个脚本的默认角色不同：C5 脚本默认电脑监听，S3 脚本默认电脑主动连接。BAT 内容保持 ASCII，中文提示由 UTF-8 Python 输出。

超时、重连及速率刷新参数必须为有限数值，且不超过 86400 秒。Profile 键使用参数的下划线形式，如 `peer_port`、`usb_port`。未知键、重复键、错误类型、非法选项和非有限数值会被拒绝。配置中的相对 `usb_log` 路径以 JSON 所在目录为基准；命令行相对路径以当前目录为基准。

## COM 与虚拟串口

本程序只打开已有 COM，不创建或安装虚拟串口。若业务上位机只支持 COM，先用虚拟串口工具创建一对端口：本程序打开一端，业务上位机打开另一端，同一个端口不能同时被两者占用。

真实串口默认 1152000、8N1，理论载荷约 115.2 kB/s，可能限制 SPI/Wi-Fi 的吞吐。虚拟串口是否受波特率影响取决于驱动。这里的波特率只控制电脑本地串口，不会修改设备 UART 波特率或 CH32 SPI 时钟。

TCP/UDP 业务桥接必须指定 `--com`；列举串口、打开配网页面和 GUI 独立 USB 配置不要求启动业务桥接。

原 capture 文件接收功能及对应预设已移除。旧自定义 profile 含有 `capture` 字段时会提示改用 COM；同一文件中的其他有效 profile 仍可使用。旧界面状态中的文件路径和输出模式会被忽略，网络、COM 和设备草稿继续恢复；若原先选中已移除的预设，需手动选择有效的 COM 桥接配置。历史采集文件保留，USB 文本日志、运行日志导出和设备配置备份继续可用。

## C5/S3 配网页面与 USB 诊断

先长按配网按键达到 3 秒。C5 为 GPIO24 / `ESP32-C5-Setup` / 出厂密码 `change-me-c5`；S3 为 GPIO4 / `ESP32-S3-Setup` / 出厂密码 `change-me-s3`。已修改密码时使用当前 AP 密码。按型号打开网页：

```powershell
py -3 -B tcp2com.py --device c5 --open-config
py -3 -B tcp2com.py --device s3 --open-config
```

此命令只打开浏览器后退出，不启动数据桥接。普通业务模式访问会返回 403。网页可选择三种接口、联网模式、频段、AP/STA IP、网络角色、端口、超时和队列容量；明确“保存并重启”才写 NVS。进入配网、保存重启都会中断业务网络，应按修改后的地址/角色重新连接。LED/按键有效电平、GPIO 和 SDK 设置仍属于固件编译配置。

可在数据桥接同时读取独立的 C5/S3 **原生 USB Serial/JTAG** 日志。以下为 C5 示例，S3 示例见快速使用章节：

```powershell

```

USB 日志端口不能与业务 COM 相同。终端以 `USB |` 前缀显示日志，文本另存为追加日志；不向 TCP、UDP 或二进制载荷文件插入内容。解析并缓存已有 `stats` 字段，包括 IP、信道、RSSI、PSRAM 队列、SPI 错误、丢弃及栈余量；未知日志原样保留。

USB 不可用/断开时通道每 2 秒重试，网络桥接继续。只看日志时不发送 USB 数据；GUI 明确读取/保存时才发送配置命令，命令和回复不写入日志文件。程序不主动脉冲 DTR/RTS；打开串口时线路的实际电气行为仍需实板确认。日志与配置共用本程序内同一个 COM 连接；与其他监视/下载工具不能同时占用同一端口。

## 统计、稳定性与故障排查

- 底部约每 0.25 秒刷新，速率为约 1 秒滚动平均。分别显示网络接收、本地写入、本地→网络发送、两方向队列和累计本地丢弃；UDP 另外显示收发包及来源拒收数。
- `网络→COM待写` 与峰值统计队列中的实际字节，不包含写线程已取出、正在合批或写入的字节；`正在写` 显示单次驱动调用的请求字节和已等待时间。`COM写均值/最大`、短写/超时和入队耗时为进程运行期间累计统计。写入返回只表示本地驱动接受，不证明虚拟串口对端应用已消费。
- 每个方向最多 128 块，每块 16 KiB，约 2 MiB，不含正在处理的批次。TCP 队列满时暂停读取，保持顺序；真实串口或 UDP 上游仍可能继续发送并溢出。
- TCP 客户端默认每 2 秒重连；TCP 服务端断线继续监听。重连前后清理队列，并检查连接代次；发送线程在等待队列后重新读取当前连接，避免误丢新会话数据。
- 串口写超时不可靠地报告已经发出的部分，未确认部分记为丢弃，不盲目重放。断线时队列清理也计入丢弃。UDP 发送部分成功时分别记录已发字节和剩余丢弃量。
- 本地丢弃为零不能证明 SPI、Wi-Fi 或主控 FIFO 没有丢包；应结合设备 USB 诊断及应用序号/校验。TCP/COM 不保留图像帧或 read/recv 块边界。
- 确认 TCP 连接方向、Windows 防火墙、端口占用、设备当前 IP。电脑监听 `0.0.0.0` 不代表 CH32 也应连接这个地址。
- S3 USB 配置超时时，核对是否选择 ESP32-S3、是否使用原生 USB 接口，以及是否长按 GPIO4 进入配网。旧 C5-only 上位机需要更新，业务串口和 USB 配置串口不能混用。
- Keepalive 不是即时断线检测，Windows 探测次数可能由系统控制。真实吞吐、双频表现及长时稳定性需在目标电脑和板上验证。
- `Ctrl+C` 或关闭控制台退出桥接。关闭 ESP-01S 复位窗口只隐藏窗口，透传继续；USB 诊断随主程序退出。

## ESP-01S 独立复位窗口

仅 `--device esp01s --mode tcp-client` 启用；可用 `--no-reset-ui` 完全关闭。命令行入口左键点击或按 `R` 打开独立窗口，打开本身不发送请求。窗口中从首次点击起 3 秒内点 5 次才发送一次请求；关闭窗口只隐藏，不停止透传或重连。

控制连接使用独立 TCP 8081，先验证 `ESP01S-RESET/1 READY`，随后发送带唯一编号的 `RESET`。只收到匹配编号的 `DONE` 才显示完成。发送后掉线/超时为“结果未知”，不会自动重发；重复编号不重复执行。详细协议见 `README_tcp2com.txt`。

ESP-01S GPIO0 开漏连接外部主控低有效复位脚、外部上拉 3.3 V，执行时拉低约 1 秒；它也是启动配置脚，启动波形须实测。该功能是复位，不等同硬件急停。控制服务无身份认证，仅用于可信局域网。

C5 和 S3 分别使用独立的 `C5-RESET/1` 和 `S3-RESET/1` 控制协议，复位输出须先在对应设备配置中启用；旧 S3 固件需升级。SPI GPIO12 是主控→设备的软件链路复位输入，不能用于电脑远程复位外部主控。上位机不能远程控制设备 LED、按键或触发配网。
