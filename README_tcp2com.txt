一、安装与启动

1. 在程序目录安装 Python 依赖：
   CLI/Tkinter：py -3 -m pip install -r requirements-tcp2com.txt
   新版桌面：py -3 -m pip install -r requirements-web.txt
   局域网服务：py -3 -m pip install -r requirements-lan.txt
2. 新版前端首次构建：进入 frontend，执行 npm ci、npm run build。
   工作台默认使用原始暖灰/米白/灰绿色，并支持深色液态玻璃风格，桌面 Chromium/WebView2 支持背景折射；手机和平板的浮层卡片同样启用背景折射，普通主页面大面板保留轻量材质，切换条滑块保留折射，菜单行高亮使用静态玻璃。
   效果随前端本地打包，不依赖 CDN 或在线背景图；支持系统“减少动态效果”。授权说明见 third-party-licenses.txt。
   “当前设备”左侧“外观”可选原始浅色、深色、跟随系统；首次默认浅色。深色为近纯黑背景、深紫灰卡片、紫色控件与浅紫高光/光晕；设备自动重连使用绿色开关，成功/警告/错误保留状态色。网页按当前浏览器站点记忆，桌面独立保存到%LOCALAPPDATA%/WiFiBridge/appearance.json；不写设备配置、不向局域网其他终端同步。启动前应用主题与窗口底色；保存失败时本次外观仍可使用并显示提示。
   界面文字与操作区域统一放大：桌面正文14px、主控件至少42px，触屏正文16px、操作行至少48px。侧栏、菜单和窗口同步扩大，中等宽度优先显示连接/设备操作，日志图表位于下一行，手机单列纵向滚动。
   各切换条点击时直接对齐目标选项，不先落到鼠标位置；鼠标移动超过5px或触屏超过8px才进入拖动，并保留原始按下位置，普通悬停不移动；松手吸附并仅提交一次选择，触屏纵向滑动可正常滚动。不同宽度选项的位置、宽高统一约280毫秒平滑变化，快速反向、重抓与取消接续当前矩形；尺寸适配与按压膨胀分开，折射贴图按目标尺寸准备，不逐帧重建。日志计数变化不取消按住的选择。选择字段弹出玻璃面板，COM/USB COM/波特率支持手输：右侧展开区只浏览，不启动输入；点击左侧数据区或聚焦后按F2才编辑。仅聚焦或点击字段名称不输入，选完候选、Escape/Tab回到非编辑状态；Enter保留手输自定义值，明确用方向键导航后Enter选择候选。浏览焦点在列表或展开区，不重新唤起软键盘。选项高亮仅随按下或键盘选择改变。
   主操作、次操作、图标按钮统一使用圆润玻璃、细边高光和柔和阴影；文字入口保持轻量反馈，主操作保留强调色。触碰时仅玻璃层隆起、亮起并轻微形变，按住维持浮起、松手柔和恢复，连续按压接续当前状态；文字、图标和点击范围保持原尺寸，普通按钮文字不被折射，滑块仍保留按住折射。保留原生点击、键盘、表单和禁用行为，滑出、Escape与触屏纵向滚动可取消，一次有效点击只执行一次操作。效果参考Apple官方演示，属于网页近似实现。
   滑块自然静止时文字无位移折射，按住不动和拖动时保留折射，松手回落后恢复清晰；按下时明显鼓起并浮起，快速轻点松手后仍完整膨胀并柔和回落，收回时增加阻尼，减少缩小过头和反复晃动，连续按压接续当前运动；主切换条长按约增宽24%、增高38%，日志来源和开关分别适配幅度。移动保持饱满圆润，仅在加减速与反向时出现短暂局部弹性，不持续拖尖尾、偏斜或压扁；位置吸附独立完成。一层按压折射配合不折射的高光层，复用预先准备的贴图，拖动复用贴图，效果基于现有网页库近似实现。开关型设置使用胶囊玻璃滑钮，清空原密码保留玻璃勾选框；高级参数平滑展开/收起并保留输入。菜单定位和玻璃准备完成后显示，直接在菜单位置展开圆润玻璃卡片，移除箭头下的独立圆片和先收拢、浮起的阶段，关闭反向收回；局域网连接面板共用开合进度，从靠近入口的一侧展开，不覆盖入口按钮。完整行程约380毫秒，反向按剩余行程接续当前画面。轮廓、圆角、阴影联动，背景采样固定，文字原尺寸清晰，不逐帧重建贴图。卡片更通透、标题更轻，行高亮不叠加折射；开合轮廓始终位于最终卡片内，数据区保留可点。
   卡片光晕在鼠标进入时从各自默认位置平滑追向指针，移出后平滑归位，返回途中再次进入从当前坐标接续。主卡片、浮层及按钮共用光照控制，触屏不模拟悬停，减少动态效果和隐藏页面恢复静止位置；光照变化不重建折射贴图。分页静止时不裁切膨胀控件，切页期间仍裁切离场画面；配置分页两侧预留16px视觉空间，局域网内部滚动区也预留按钮膨胀空间，字段和点击范围保持原位。

   网络角色、日志/流量、配置分页、USB/HTTP与日志来源在确认后按方向滑动切页，约270毫秒；拖动时只有玻璃滑块跟手，内容保持原页，松手确认后才切换，取消或回到原项不切页。点击/键盘使用相同过渡，快速反向接续当前画面；草稿与暂停日志滚动位置保留，离场画面不可交互、不重复调用设备接口。高度平滑变化，结束后统一更新大面板贴图；触屏选中项去掉玻璃下方的矩形焦点框，由玻璃轮廓提示焦点，减少动态效果时直接切换。
   选项支持方向键、Home/End、Enter、Escape；抽屉、确认框和局域网面板支持平滑打开、关闭。
   菜单、局域网面板、桌面配置/诊断/复位/帮助与确认框使用通透中央和较厚的边缘透镜，折射下层真实内容，卡片内文字和输入框不参与滤镜。开合复用已解码贴图，局部映射与强度跟随轮廓；不逐帧重建画布或替换全页滤镜。高级参数使用轻玻璃，手机二级页面保留结构并使用玻璃导航栏。不支持SVG背景滤镜时回退磨砂。平板配置/复位使用独立的固定2px轻模糊遮罩，菜单背景采样面固定。局域网窗口为独立视口浮层，展开前完成边界约束和尺寸分配，连接状态及终端列表在固定框内滚动，内部预留滚动条空间；旋转和可视区域变化时重新定位。局域网面板关闭时固定位置、尺寸和内容，完全隐藏后移除，避免突然消失或视口变化引起跳动；关闭后恢复入口焦点，其他窗口已获得焦点时不抢回。关闭面板不会断开服务连接。
   手机窄屏（进入时不超过760px）的诊断、配置和远程复位改为全屏二级页面，顶部“返回＋标题”，配置底部保留保存按钮。新页从右滑入、工作台轻微左移，返回沿相反方向，统一约320毫秒，文字不缩放，不再裁剪揭幕或淡入模糊背景。工作台保留挂载并冻结大面积背景采样，小型玻璃控件保留。顶部/浏览器/系统返回先关闭选项菜单或保存确认，再回工作台；前进可重入，刷新保留页面层级。返回保留草稿、日志与页面滚动并恢复入口焦点，横竖屏与键盘按可视区域适配，当前页不突然变抽屉；宽屏继续抽屉，帮助/确认形式保持原样。减少动态效果时直接切页。
   透镜保持圆润饱满，主体跟手、边缘短暂弹性，松手柔和吸附；开关使用略宽的圆角透镜，桌面/触屏轨道宽64/72px，拖动行程仍为22/26px。设备自动重连在明暗主题中都用绿色，关闭为中性无绿色轨道，颜色与位置共用0–1进度；拖动实时、点击轨道/文字/键盘统一约240毫秒过渡，支持中途重抓、反向和取消，不自动保存设备。
   外观切换约300毫秒，背景、文字、边框和玻璃色调同步渐变，快速反向接续当前颜色；首次加载、相同明暗外观和减少动态效果不额外播放。保留输入、连接、滚动和导航记录，返回后刷新保持最新外观；手机复位页保留当前设备地址/端口和任务状态，进入、返回或换主题不触发复位。
3. 本机工作台：启动_新版界面.vbs；启动_新版界面.bat 用于构建和诊断。
4. 手机/其他电脑：启动_局域网服务.vbs，使用管理窗口生成的完整链接或二维码。
5. Tkinter：启动_图形界面.bat；原 CLI 使用各启动 BAT 或 tcp2com.py。

在线网页需要服务电脑上的 Python 后端。网页操作的 COM、USB 属于服务电脑；持有效连接链接可自动接入，无需批准。
关闭网页不停止后端业务；关闭管理窗口停止服务并释放设备。首次访问固定在线网址时使用完整连接链接。
服务参数会记住网卡、监听地址/端口和来源，同网卡换 IP 后更新链接。默认网页服务端口 8765，与设备业务端口 8080 不同。

二、选择设备与接口

C5：2.4/5GHz/AUTO；原始 UART=0、UART GPIO 流控=3、四线 SPI 简易写入=4。
旧 C5 SPI WBR=1、UART WBR=2 停用。S3：仅 2.4GHz，保留原始 UART=0、SPI WBR=1、UART WBR=2。
不要把两种固件的接口编号和 MCU 库混用。

C5 SPI 接线：SCK=GPIO23、MOSI=GPIO10、MISO=GPIO9、CS=GPIO5，另需供电和共地。
无需 READY、复位线；GPIO11/12 不再承担握手/复位，UART/UHCI 不初始化。
MCU 库：C5 固件 mcu_library/，本地可导出到 D:\ESP\spi库，只复制 wifi_spi.c/.h。
MCU 实现五个板级端口，调用 wifi_spi_init()、wifi_spi_write(data,length,&written)。
TCP 每批最多 4096 字节，自动多批/尾批；UDP 每次调用一包，最多 512 字节。
SPI 只支持 MCU→C5→网络，电脑发送的业务数据不会送到 MCU；需要下发指令时选 UART。
成功表示 C5 缓存接收，不表示电脑已收到；结果不确定不能直接重发。初始化与批量时序见库 README。

C5 UART GPIO 流控：flow_pin 1/2/3/4 对应 GPIO23/10/9/5，高暂停、低允许，MCU 输入需上拉。
流控线不能与启用的复位线共用，默认 MCU 响应/尾随预算为 5ms 加 4096 字节，实际必须验证。

三、设备配置

1. 选择 ESP32-C5 或 ESP32-S3，连接正确的原生 USB COM。
2. C5 长按 GPIO24 至少3秒，S3 长按 GPIO4，进入配网后读取设备配置。
3. USB 不要求电脑连接 ESP Wi-Fi，不需要启动业务桥接；HTTP 使用配网热点和 http://192.168.4.1/。
4. 编辑接口、Wi-Fi、网络角色、IP/端口和缓存，查看摘要，明确保存并重启。
5. 保存结果未知先重新读取，不能盲目重复保存。

C5 API 为 c5-config-2，保存需当前会话和修订号。旧 SPI 配置恢复时不初始化业务引脚，必须明确保存重启。
旧备份保留网络端口（含8081）及未生效的复位/流控选择，接口要求重新选择；实际选择 UART 后再检查冲突。
固件自身迁移旧 SPI NVS 会清除未生效的复位选择，保留有效网络参数。
导入备份、恢复草稿和启动程序不写 ESP。密码空白表示保留，清空 STA 密码必须明确选择。
启动、型号/地址/端口切换后重新读取设备。无密码草稿和服务参数保存在本地状态文件，不提交仓库。

四、电脑网络与 COM

电脑 TCP 客户端对应 ESP TCP 服务端；电脑 TCP 服务端对应 ESP TCP 客户端。UDP 填双方实际地址和端口。
0.0.0.0 只用于电脑监听，不能作为 ESP 连接目标；电脑实际网卡地址请用管理窗口或 ipconfig 核对。

C5 主动连接电脑示例：
py -3 -B tcp2com.py --device c5 --mode tcp-server --listen 0.0.0.0 --port 8080 --com COM5

电脑连接 C5 示例：
py -3 -B tcp2com.py --device c5 --mode tcp-client --host 192.168.4.1 --port 8080 --com COM5

profiles 示例：
py -3 -B tcp2com.py --config tcp2com_config.json --profile c5-spi-tcp --com COM5
py -3 -B tcp2com.py --config tcp2com_config.json --profile s3-client --com COM5

profiles 只配置电脑，不自动修改 ESP 接口或 NVS。业务 COM 可为真实串口或虚拟 COM 对的一端，不与其他程序共用同一端口。
原生 USB 日志/配置 COM 与业务 COM 不同。电脑 baud 不会改变 MCU SPI 时钟或 ESP UART 波特率。
真实 COM 1,152,000 baud、8N1 的理论载荷约115.2kB/s，可能限制 SPI/Wi-Fi 链路。

五、复位、日志与验证

外部 MCU 复位使用各型号独立 TCP 8081 协议，3秒内点击5次才发送；打开窗口不发请求，结果未知不重试。
C5 仅 UART 模式可启用复位输出，默认关闭；SPI=4 不启用。ESP-01S 的 GPIO0 复位接法和启动约束以固件为准。
控制服务用于可信网络，不代替硬件急停。USB 日志、队列和丢弃计数用于判断瓶颈，网络接收不等于 COM 写入成功。
