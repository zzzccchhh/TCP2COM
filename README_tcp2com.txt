tcp2com 原 ESP-01S 协议与操作说明

当前通用功能、ESP32-C5 TCP 服务端/UDP、JSON 配置和 USB 诊断请先阅读 readme.md。
本文件后半部分保留 ESP-01S 8081 复位协议，C5 不支持此协议。

1. 安装 Python 3。
2. 在此目录运行：py -3 -m pip install -r requirements-tcp2com.txt
3. 修改“启动_tcp2com.bat”中的 T2C_HOST、T2C_PORT、T2C_COM 和 T2C_BAUD。
4. 双击启动 BAT。

显示编码：
- BAT 文件仅使用 ASCII 字符，避免 Windows cmd.exe 将 UTF-8 中文提示显示成乱码。
- Python 输出使用 UTF-8；启动 BAT 会先切换到代码页 65001。

日志和实时监测：
- TCP 连接、断开/重连等待等状态只在状态变化时显示一次。
- 终端底行每 0.25 秒刷新，速率采用约 1 秒滚动平均，减少短时间片导致的显示跳动。
- 显示网络接收、本地写入、本地到网络速率、双向队列积压块数，以及累计本地丢弃量。
- TCP 收到速率和串口写入速率分开显示，便于判断是网络输入变慢还是串口端跟不上。
- 若重定向到文件，终端不能固定底行刷新，会降频输出速率行。

性能与稳定性：
- TCP->串口队列达到上限时使用背压暂停 TCP recv，而不是任意丢弃队列最旧的数据，尽量保持图像/二进制流顺序。
- 队列块大小 16 KiB，最多 128 块；实际队列缓存上限约 2 MiB（不包含正在处理的批次）。
- 串口输出聚合批次上限 64 KiB，但拆成 4 KiB 分段写，便于及时统计写入进度；这可能增加少量系统调用开销。
- 连接代次标记用于过滤旧 TCP 连接残留数据。
- TCP Keepalive 检测不是即时的。Windows 的探测次数通常仍受系统设置影响。
- 没有 RTS/CTS 硬件流控时，若真实串口持续输入速度超过消费速度，任何用户态程序都无法保证无限期无丢失；可视设备支持情况调整流控与缓冲区。

诊断建议：
- 若队列块数持续上升到 128，说明 TCP 输入比串口写出更快，发生了背压。
- 若 TCP 收到速率和串口写入速率同时下降、队列接近 0，瓶颈更可能在 ESP/Wi-Fi/TCP 上游或发送端没有持续供数。
- 若累计丢弃量增加，查看连接断开、串口写超时或队列清理日志。
- 若累计丢弃量不增加但图像仍缺帧，需要检查 ESP/MCU UART 缓冲溢出，以及接收端图像帧同步/长度/校验逻辑；TCP 和串口都是字节流，read/recv 的分段边界不是图像帧边界。

当前原启动 BAT 默认参数：192.168.4.1:8080，COM1，1152000 baud，8N1。
注意：请将 COM1 修改成实际使用的本地串口号。

远程复位（需要配套新版 ESP 固件）：
- 双击原启动 BAT 后只显示命令行桥接，不额外打开图形主窗口，也不自动弹出急停窗口。
- 命令行底部状态区显示“[ 打开急停 / 复位窗口 ]”，下方显示完整的速率和丢弃量，按列宽分行；用鼠标左键点击入口（或在命令行中按 R）才打开独立的急停窗口，入口本身不发送复位请求。窗口很窄时入口缩写为“[复位]”或“[R]”。
- 关闭急停面板只隐藏面板，串口透传、TCP 连接和自动重连继续运行；再次点击入口会显示同一个面板，不重复创建。
- 未触发复位时关闭面板会清零未完成的点击计数；已触发时关闭不会取消请求，重新打开可查看执行状态和结果，等待期间仍禁止重复触发。
- 在命令行按 Ctrl+C 或关闭命令行窗口退出整个桥接。
- 鼠标入口使用 Windows 控制台输入事件；运行期间关闭快速编辑以接收点击，正常退出时恢复原输入模式，Ctrl+C 保持可用。日志刷新、中文宽度和控制台缩放后会更新入口的点击区域。
- 输出重定向、非 Windows 环境或无法访问原生控制台时不提供鼠标入口，仍运行桥接并输出提示；不同终端宿主的实际鼠标行为需分别验证。
- 从首次点击起 3 秒内点击 5 次才发送一次请求；超时清零，等待响应期间按钮禁用。
- ESP GPIO0 接外部单片机的低有效复位脚，两端共地。使用开漏输出，外部复位线需上拉到 3.3V；不能接上拉到 5V 的复位线。
- GPIO0 平时释放为高电平，执行时拉低约 1000ms，再释放；拉低期间 GPIO2 每 50ms 翻转一次（约 10Hz），结束后恢复原有灯态。
- GPIO0 同时决定 ESP 启动模式；上电时必须保持高电平，需检查外部复位电路、电容、按键是否会把它拉低。不要把 GPIO0 接回 ESP 自己的 RST。
- 该按钮执行外部主控复位，不能替代硬件急停；车辆是否停机取决于主控复位及重新启动时的电机输出。
- 原始透传仍走 8080，独立复位控制走 8081。可在 BAT 中修改 T2C_CONTROL_PORT；固件需同步修改 ESP01S_RESET_CONTROL_PORT。
- 控制端口只用于可信局域网，没有身份认证，不要转发到公网。复位期间桥接不主动暂停或清空透传队列。
- 只有收到对应请求的 DONE 才显示“复位完成”；这仅确认 ESP 已释放输出，不代表主控已完成启动。
- 若发送后断网或超时，显示“结果未知”，不会自动重发；ESP 仍会在计时到期后释放 GPIO0。恢复网络后检查设备再决定是否重新操作。
- 固件保留本次开机最近 8 个请求编号，重复编号不重复产生脉冲；执行中的新编号返回 BUSY，额外并发控制连接可能被关闭。
- 旧固件不支持 8081 时按钮会提示失败，不向透传端口发送控制命令。
- 不使用急停入口和弹窗功能：增加 --no-reset-ui。弹窗使用 Python 标准库 tkinter，Windows Python 安装时需包含 Tcl/Tk；不可用时提示并继续控制台桥接。
- 窗口会按字体缩放和多行结果提示自动增高，避免高 DPI 下裁掉复位状态。

控制协议（ASCII，每行以 LF 结束，每个连接一个请求）：
  ESP -> PC: ESP01S-RESET/1 READY\n
  PC -> ESP: RESET <32位小写十六进制请求编号>\n
  ESP -> PC: STARTED <编号>\n
  ESP -> PC: DONE <编号>\n
  已完成的重复编号直接返回 DONE；忙时返回 BUSY <编号>，非法请求返回 ERROR <原因>。
  控制会话最多 3 秒。数据连接使用 1ms 写等待，并在每次写入返回后处理复位计时和灯态；未写出的数据保留在环形缓存中。
  复位仍采用软件计时，系统调度会带来少量延迟；实际波形需在满速和断网情况下上板测量。

软件验证（从仓库根目录执行）：

  固件控制状态机的主机测试与运行命令见 esp01s/test/test_remote_reset_host/README.md。
